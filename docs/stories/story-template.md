# Story Template

Use this structure for every standalone story in `docs/stories`.

## Files

- `story-XX-name-design.md` for the story goal, scope, and behavior
- `story-XX-name-implementation.md` for the implementation plan, tasks, and validation

## Recommended Sections

### Design

- Goal
- Scope
- Story Slice
- Recommended Approach
- UI or API Design
- Behavior or Data Flow
- Testing
- Dependencies
- Story Boundary

### Implementation

- Goal
- Architecture
- Tasks
- Validation
- Risks

## Notes

- Keep one story number per feature slice.
- Keep design and implementation files next to each other.
- Use the backend story map as the numbered overview for backend work.
